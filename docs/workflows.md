# Workflow provenance

CreateSpace's H3 compiler is a focused implementation of the native ComfyUI graph used by James Knox's [Oyama AI Video Studio](https://github.com/jamesk9526/Oyama-AI-Video-Studio). Inspected reference: `electron/native/lib/workflow.ts`, `modelSelection.ts`, `electron/calculations.ts`, and workflow tests in the local Studio checkout. No UI, CSS or state store was copied from that application.

Template `h3-native-av/4` is a pure TypeScript graph factory with shared base topology and three conditioning variants. It emits ComfyUI API JSON. Text and first/last-frame generation use `MiniMaxH3ImageToVideo`; references use `MiniMaxH3ReferenceToVideo` with dotted image/video/audio socket names. Sampling uses RandomNoise, BasicGuider, res_multistep, simple, and SamplerCustomAdvanced. Video and audio VAEs decode the same joint latent, then CreateVideo feeds SaveVideo node 19. Installed `MiniMaxH3SaveLatent` additionally checkpoints the sampler's AV latent at node 204 without adding another media output.

Ref2VA's `ref_image_size` field is exposed as Match output / Maximum identity detail. This is the native `match|max` enum, not an invented identity-strength control. The [Comfy-Org node implementation](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy_extras/nodes_minimax_h3.py) caps maximum mode at 2048 on the short edge and never upscales beyond the original; additional reference tokens increase memory and runtime. Output dimensions remain independently controlled. Explicit Text/Image modes deactivate stored reference/record attachments; legacy invalid text drafts still migrate to Ref2VA.

Dimensions must be multiples of 32. Length rounds upward to the H3 17k+5 frame grid at 24 FPS; the inspector shows the actual encoded duration. Native Quality uses the source Studio's 30-step preset (its `applyPreset('quality')` configuration). Turbo 8 requires the mode's detected LoRA. Ref2VA Turbo applies 6/3 sigma shifts. Negative conditioning is not submitted. Base model loader filenames come from the connected server; model files are never downloaded by CreateSpace.

SaveVideo emits MP4/H.264. The compiler detects the current dynamic-combo schema and supplies `format.codec`; older schemas receive `codec`. This was verified against the live ComfyUI 0.37.0 instance using MCP validation and actual renders.

The compiler deliberately omits the prior app's optional attention patches, GPU routing, upscaling and experimental sampling. These should become explicit module capabilities with independent tests.

Use `pnpm exec tsx scripts/prepare-live.ts` to create low-resolution, fixed-seed T2V/I2V/Ref2VA smoke graphs under ignored `artifacts/live/`. This imports a small test reference into ComfyUI but does not queue generation. Validate those graphs through Comfy MCP before running them. A completed MCP render validates the graph; a completed application render also validates IPC, job tracking, managed storage and media playback.

## ZImage

Template `zimage-aura/1` follows the Studio implementation and the Comfy-Org ZImage templates. It loads a ZImage diffusion model, the Qwen 3 4B Lumina2 text encoder and `ae.safetensors`, applies AuraFlow shift 3, then samples with `res_multistep` and `simple`. Turbo defaults to 8 steps and CFG 1 with zeroed negative conditioning. Base defaults to 40 steps and CFG 4 and submits the editable negative prompt; its accepted source ranges are 28–50 steps and CFG 3–5. Dimensions are 256–2048 and 32-pixel aligned.

Only SaveImage node 10 is treated as a completed image; PreviewImage is ignored during output reconciliation. Generated images are managed project assets. The typed H3 handoff sets the same project's first frame and retains unrelated H3 draft values. Global promotion creates a managed library copy and leaves the project original intact.

Run `pnpm exec tsx scripts/prepare-zimage-live.ts` to compile fixed-seed 256×256 Turbo and Base API graphs against the currently connected server under ignored `artifacts/live/`. Validate each with Comfy MCP before queueing. Model presence and graph validation are separate from an app-driven live render.

## LTX 2.5

Template `ltx25-distilled/1` adapts Studio's `src/lib/ltx25Workflow.ts`. It requires the LTX 2.5 **distilled** transformer, its Gemma encoder and separate video/audio VAEs. The dev transformer is never substituted. At 24 FPS, integral seconds map to `seconds × 24 + 1` frames, satisfying the 8n+1 grid. Dimensions are multiples of 64 so Quality's half-size first stage stays 32-pixel aligned.

Turbo uses the source first-stage manual sigma schedule and Euler ancestral sampling. Quality samples at half width/height, applies the installed LTX latent x2 upscaler and runs the source refinement sigmas. Both decode video and audio into CreateVideo, and only SaveVideo node 43 is a managed output. The UI reports stage-aware progress. The first-frame path uses current ComfyUI `ResizeImageMaskNode` dotted API keys before LTX image conditioning in the first and optional second stage.

Licon MSR is optional. Up to four ordered picture slots and a background attach to the installed MSR LoRA loader. Turbo guides the first stage; Quality guides the refined latent **after** upscaling. `LTXVCropGuides` receives the final sampled video latent and corresponding conditioning before decode. This was established by a real regression: without cropping, a requested 25-frame video saved 65 frames. The corrected real output saved 25 frames, H.264 video and AAC audio. [Licon MSR's README](https://github.com/liconstudio/ComfyUI-LTX2.5-MSR) documents guide cropping.

Run `pnpm exec tsx scripts/prepare-ltx-live.ts` for Turbo and Quality validation graphs; `--msr` uses an existing uploaded first frame from the ignored live test data. Comfy MCP validated all four variants with zero errors/warnings. `node scripts/ltx-live-smoke.cjs` tests Turbo T2V through the app; `--image --quality` and `--image --quality --msr` test the other routes. Add `--packaged --reuse-complete` to reopen a saved output in the packaged app without resubmitting it.

## LTX Ripple

Template `ltx-ripple-v11/1` adapts Studio's `src/lib/ltxRippleWorkflow.ts` and its selected LTX 2.5 distilled model. The graph requires `LTX25_Ripple_v11.safetensors`, Gemma, both LTX VAEs and the IC-LoRA guide/crop nodes. Default LoRA strength is 1.35, motion guidance 1, CFG 1, Euler/simple sampling and 8 steps. [The creator's model card](https://huggingface.co/WepeNerd/LTX-Ripple) describes the first-frame editing behavior and strength.

Integral durations of 2–20 seconds produce 49–481 frames on the 8n+1 grid. Dimensions are 32-pixel aligned. The replacement image precedes the source frames in the motion guide. `LTXVCropGuides` removes guide latents before decode; SaveVideo node 29 is the only managed output. Source audio passes from GetVideoComponents to CreateVideo, rather than decoding newly generated audio.

Before upload, FFmpeg creates a temporary H.264/AAC source copy: the requested span, 24 FPS, selected canvas, and exactly `output frames − 1` source frames. Original assets remain intact; the snapshot keeps source ID, frame rate and duration. Video duration takes precedence over container audio duration. Copies are removed after upload; the server's `/features.max_upload_size` controls the input cap (100 MB fallback for older servers), with a shorter-clip remedy. The preview toolbar switches between source, replacement frame and result. Long-video chunking remains a separate unfinished milestone.

`node --import tsx scripts/prepare-ripple-live.ts` writes a validation graph using existing ComfyUI inputs. Comfy MCP validated it with zero errors/warnings. `node scripts/ripple-live-smoke.cjs` renders through the app using existing real ZImage/LTX assets; `--packaged --reuse-complete` reopens the result. The full-span real test saved 512×320 H.264 video, 49 frames, 2.041667 seconds, and 2.005 seconds of 48 kHz AAC. `node scripts/verify-ripple-audio.cjs` compared 1.8 seconds of decoded source/output audio and measured correlation 0.9971.

## FireRed Photo Edit

Template `firered-image-edit/1` adapts Studio's `src/lib/fireRedEditWorkflow.ts`. It detects installed FireRed safetensors or a supported GGUF loader/model (Q4_K_M preferred), Qwen 2.5 VL encoder and `qwen_image_vae`. GGUF selection is covered by capability fixtures; no FireRed GGUF is installed on the current server, so no live GGUF claim is made.

The source is scaled/center cropped to the selected canvas, encoded as the initial latent and passed to positive/empty-negative `TextEncodeQwenImageEditPlus`. Up to two ordered references feed image2/image3. Both profiles use AuraFlow shift 3.1, CFGNorm 1, Euler/simple and denoise 1. Turbo requires the detected FireRed 8-step Lightning LoRA and uses 8 steps/CFG 1. Quality uses 40 steps/CFG 4 without Lightning. SaveImage node 14 is the sole output. [FireRed's ComfyUI model card](https://huggingface.co/FireRedTeam/FireRed-Image-Edit-1.1-ComfyUI) documents the model family.

Ripple's first-frame extraction hands off the selected canvas and source image; the selected edited result returns its decoded dimensions while preserving Ripple's video and controls. Real 512×320 PNG outputs passed Turbo with no references, Quality with one reference, and Turbo with two references. The Quality result also produced a real 49-frame Ripple video with source audio correlation 0.9971. Validation graphs are generated by `scripts/prepare-photo-edit-live.ts`; app checks use `scripts/photo-edit-live-smoke.cjs` (`--quality`, `--references`, `--packaged --reuse-complete`). New submissions are tracked by their new job ID; existing outputs are reopened without generation.

## Continue / Extend — last or selected frame

Template `h3-continue-frame/4` follows Studio's `src/lib/continuation.ts` and its last-frame route, extended with a probed selected-frame source range and the installed H3 motion extender. Last/selected methods extract the chosen decoded source frame in main, snapshot optional source scene context (including resolved descriptions), original record IDs and the authored next action, then compile H3 image-to-video. Native uses the existing 30-step recipe; Turbo uses FL2V Turbo 8. Frame routes retain every generated head frame. Nearest-grid length is `max(22, 5 + round((round(seconds × 24) − 5) / 17) × 17)`; one requested second delivers 22 frames/0.916667 seconds. Normal H3 generation keeps its existing upward-rounding rule.

After SaveVideo node 19 completes, the bridge checkpoints the raw managed beat before assembly. FFmpeg fits both clips to the selected canvas, normalizes to 24 FPS, pads missing/short audio, and concatenates video/audio without crossfade or overlap removal. Originals and raw beats remain available. SQLite v3 retains the source, generated beat and job IDs on the joined asset. Restart recovery uses the same Comfy prompt and downloaded beat; existing joined output is recognized by its derivation job ID.

Both profiles passed MCP validation with zero errors/warnings and app-driven real generation. A 49-frame LTX source plus a 22-frame H3 beat produced 71 frames, 512×320 H.264, 24 FPS and 2.958333 seconds of synchronized AAC/video. Source audio correlation was 0.9993; generated-beat audio correlation exceeded 0.9957 at the correct join offset. A real assembly failure was recovered after fixing explicit output frame rate, reusing the original Turbo prompt ID. Variable-FPS/silent-source/short-audio fixtures verify normalization; managed media responses support byte ranges and seeking after restart.

Use `scripts/prepare-continue-live.ts`, `scripts/continue-live-smoke.cjs` (`--native`, `--packaged --reuse-complete`), `scripts/continue-media-smoke.ts` and `scripts/verify-continue-audio.cjs`. Imported sources have no generation prompt or saved H3 tensors. Selected-frame extraction floors the requested time to the probed source frame grid and rejects times beyond the last decoded frame. Assembly retains the normalized source prefix through that frame, trims its audio to the same prefix and appends all generated frames/audio. A real 0.5-second selection retained 13 source frames plus 22 new frames, delivering 35 frames/1.458333 seconds at 512×288 with H.264/AAC in both Turbo and Native. Long Ripple chunks and automatic script sequence execution remain unavailable.

## Continue — motion and trailing AV latents

Inspected the installed `ComfyUI-Minimax-H3-Extender/nodes.py` and MCP schemas for `MiniMaxH3VideoExtender`, `MiniMaxH3LoopTrim`, `MiniMaxH3SaveLatent` and `MiniMaxH3LoadLatent`. Supported context runs are 5/22/39 frames, matching H3's temporal phase. New frames are `max(17, round(seconds × 24 / 17) × 17)`; render length is new + context. Node 202 conditions the new head using `always_extend`, `video`, `head`, timeline audio and equal visual/audio context lengths. Node 203 trims the repeated context from decoded video/audio before node 18/19 saves the new beat. Assembly appends the trimmed beat to the full source; it does not remove the source tail or additional generated head frames.

The frames path uploads a main-prepared 24 FPS/canvas-normalized bounded source tail. Missing or short audio is padded. Direct latent reuse loads the exact source checkpoint at node 205 and connects its AV tensor to node 202's `prev_latent`; the source frames remain available for the extender's compatibility checks. Compatible video/audio tails are sliced directly, skipping their decode/re-encode conditioning round trip. The sampler's newly generated joint latent is saved at node 204 for the next continuation. Checkpoints use unique job prefixes and fixed file slots; no branch loads a directory's newest file.

Main downloads the known per-job safetensors output into managed project `contexts/`, validates a bounded envelope and both tensor streams, and associates checkpoint metadata with raw and joined video IDs. Files stay out of renderer media access and logs. Reuse stages only the selected owned checkpoint to the chosen server's output area. Auto prefers saved tensors when available, sufficiently long and canvas-compatible; Required rejects an incompatible source and Frames explicitly uses decoded inputs. Clips, old/imported media and changed canvases retain the frames fallback. The inspector explains the selected path.

Latent uploads respect the connected server's advertised upload limit and offer the frames route as a remedy when a checkpoint is too large. A live Native last-frame render exposed a queue/history publication race. Main now waits through a bounded 30-second gap, then backs off passive checks of the same known prompt. Known unresolved prompt IDs can be reconciled after restart; unknown submissions without a prompt ID are never guessed or resubmitted. Dismissal/closing remains respected during asynchronous checks. ## Long Ripple and bundled media tools

Planner/assembly provenance: Studio `src/lib/ltxRippleBatch.ts` and its main FFmpeg batch assembly. CreateSpace saves a parent plus individually recoverable chunk jobs using existing bridge primitives. Long mode processes 2–300 seconds in 2–20 second chunks, overlaps under half a chunk, and limits the plan to 100 chunks. The last source span can be temporarily padded; assembly removes the extra model frame and padded tail, blending or cutting overlaps and retaining original source audio. Each chunk uses the replacement frame and its own source-motion range; it does not claim inter-chunk latent conditioning.
